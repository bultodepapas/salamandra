Salamandra separates human authority, numerical authority, model-specific assumptions
and physical evidence. That separation is deliberate: it makes a conflict visible before
it reaches CAD or a test article.

## Source-of-truth layers

The Design Guide and `design_config.py` must agree. The guide provides meaning, units,
scope and instructions; the Python module provides exact shared constants and executable
invariants. A model-specific estimate belongs in its owning script, not in the shared
contract.

## Evidence is a loop, not a ladder

The four tags classify where a claim comes from. They do not say that every claim moves
from `[M]` to `[D]` to `[E]` to `[I]`, and they are not interchangeable confidence scores.

<Mermaid diagram={`
flowchart LR
  accTitle: Provenance classes and verification loop
  accDescr: Measurements can feed derived calculations. Estimates and inferences remain separate declared inputs. Tests can replace them with measurements or trigger corrections.
  M["[M] measured input<br/>source + conditions"] --> D["[D] derived result<br/>method + validation"]
  E["[E] estimate<br/>declared assumptions"] --> D
  I["[I] inference<br/>unverified reasoning"] --> DEC["reversible decision<br/>or research direction"]
  D --> DEC
  DEC --> GAP["gap + closure criterion"]
  GAP --> TEST["controlled test"]
  TEST --> M
  TEST --> CORR["correction if contradicted"]
`} />

A derived value can inherit uncertainty from an estimated input. Reproducible arithmetic
does not convert `[E]` into `[M]`; only evidence does.

## How a parameter enters the design

The current neutral-point chain is a useful example:

1. The planform contract fixes span, area, taper and −15° quarter-chord sweep.
2. The panel VLM calculates **NP = −75.8 mm / 25.72 % MAC**.
3. A structurally independent Weissinger-L method gives **−72.9 mm / 27.0 % MAC**;
   the difference is **2.9 mm**.
4. I-21 records the trade, assumptions and central-body limitation.
5. ADR-0040 adopts the sweep, neutral point and **−93.8 mm** target CG.
6. Design Guide v{{GUIDE_VERSION}} publishes the CAD control values.
7. Balance and flight identification remain the physical closure path.

The calculation is closed enough for controlled CAD work, while the unmeasured
central-body and flight effects remain visible. “Closed” is always scoped.

## Toolchain responsibilities

| Layer | Tool | Responsibility | Must not claim |
|---|---|---|---|
| Shared inputs | `design_config.py` | Geometry, atmosphere, mission points, speed roles, loads and released masses | Model-specific physics |
| Aerodynamics | In-house VLM, Weissinger-L, XFOIL 6.99 | Potential-flow checks, independent NP check, section-polar generation | Measured printed-aircraft performance |
| Coupled sizing | Balance, mass, propulsion, control, yaw, divergence and load scripts | Propagate declared inputs and expose sensitivities | Flight qualification |
| System verification | `verify_calculations.py` | Cross-module equality and deterministic CLI execution | External XFOIL or physical-gate completion |
| Publication | Astro Starlight, `gen-site.mjs`, `check-refs.mjs` | Mount canonical records, build indexes, rewrite links and check references | New engineering authority |
| Physical closure | E-, F-, S- and D-series work | Convert assumptions into measured evidence | A pass outside the tested configuration |

## Publication architecture

The website does not maintain a second copy of the engineering record:

```text
canonical Markdown and Python
        ↓ read only
wiki/scripts/gen-site.mjs
        ↓ generated content + normalized links + indexes
Astro Starlight
        ↓
static site + Pagefind search + sitemap + llms.txt
```

At build time, the generator derives the current release, guide version, correction
number and record counts from canonical sources. It also generates indexes for
{{ADR_FILE_COUNT}} published ADR files, {{RESEARCH_FILE_COUNT}} research threads and
{{SCRIPT_FILE_COUNT}} Python tools. Wiki-only onboarding pages use those generated values
instead of hand-maintained release labels.

## Gates that protect the record

- `check-refs.mjs --strict` rejects broken local Markdown/MDX links and unknown ADR, I,
  G or E identifiers.
- `gen-site.mjs --strict` rejects unresolved publication links except declared forward
  references.
- `astro check` validates the content schema and components.
- Markdown lint protects structural consistency in the committed onboarding pages.
- The production build creates Pagefind search and the sitemap from the same content CI
  will deploy.
- The calculation verifier proves that model boundaries share one released aircraft.

Corrections through **C{{LATEST_CORRECTION}}** remain part of the product: a correction
updates current authority while preserving the historical claim that was overturned.
